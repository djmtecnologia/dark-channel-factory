# SPRINT 2.7 — MATRIZ DE FALHAS DO WATCHDOG (ETAPA 0.8 — ESPECIFICAÇÃO TÉCNICA CONSOLIDADA)

**Status:** Especificação Técnica Operacional (Somente Análise e Documentação)  
**Escopo:** Análise explícita dos 15 cenários de falha obrigatórios (T7)

---

## MATRIZ DE CENÁRIOS DE FALHA (1–15)

| # | Cenário | Risco | Comportamento Esperado | Evidência Disponível | Estado Resultante (`UploadAttempt` / `VideoJob`) | Permite Nova Tentativa? | Intervenção Humana? |
|---|---|---|---|---|---|---|---|
| **1** | **Desktop Node desligado durante o upload** | Processo Playwright pode ter concluído ou parado no meio. | No próximo boot, watchdog compara `current_boot_time_utc > attempt_boot_time_utc` (ambos via `LastBootUpTime` UTC) e emite `EXECUTION_ISOLATED`. | `HOST_BOOT_TIME_CHECK` (`EXECUTION_ISOLATED`) | `UNKNOWN` -> `TERMINATED` *(somente se `CONFIRMED_ABSENT`)* / `UPLOAD_UNKNOWN` -> `PENDING_UPLOAD` | **Sim**, somente após `CONFIRMED_ABSENT` + evidência | Não (se reconciliação automática concluir) |
| **2** | **Desktop Node reiniciado com Playwright antigo ainda ativo** | Processo antigo continua rodando e pode publicar duplicado. | Watchdog lê State Store no startup, valida `(pid, create_time)` / Job Object e executa encerramento seguro. | `TREE_TERMINATED` (se encerrado e verificado) ou `INCONCLUSIVE` | `TERMINATED` (se `CONFIRMED_ABSENT` + `TREE_TERMINATED`) ou `UNKNOWN` | **Apenas se** `TREE_TERMINATED` + `CONFIRMED_ABSENT` | Sim, se `INCONCLUSIVE` |
| **3** | **Cloud Hub indisponível durante o upload** | Desktop Node não consegue renovar lease ou reportar status. | Após `CLOUD_HUB_DISCONNECT_GRACE_SEC`, watchdog encerra o Playwright localmente e grava evidência no Outbox local. | Evidência local no Outbox (`TREE_TERMINATED`) | `UNKNOWN` (até Outbox sincronizar e reconciliar) | **Não** até sincronizar e reconciliar | Não (sincronização automática) |
| **4** | **Perda de heartbeat com processo ainda ativo** | Processo travado ou lento sem reportar; risco de publicação tardia. | Após `WATCHDOG_HEARTBEAT_TIMEOUT_SEC`, watchdog inicia encerramento seguro (nunca presume que morreu). | `TREE_TERMINATED` ou `INCONCLUSIVE` | `UNKNOWN` -> `TERMINATED` (se `CONFIRMED_ABSENT` + `TREE_TERMINATED`) | **Apenas se** `TREE_TERMINATED` + `CONFIRMED_ABSENT` | Sim, se `INCONCLUSIVE` |
| **5** | **Processo principal (Python) encerrado, navegador ainda ativo** | Navegador órfão continua upload no YouTube. | Watchdog detecta processos remanescentes no Windows Job Object e executa `TerminateJobObject`. | `TREE_TERMINATED` após `ActiveProcesses == 0` | `UNKNOWN` -> `TERMINATED` (se `CONFIRMED_ABSENT` + `TREE_TERMINATED`) | **Apenas se** `TREE_TERMINATED` + `CONFIRMED_ABSENT` | Não |
| **6** | **Navegador encerrado, processo Python ainda ativo** | Python pode tentar relançar navegador ou reportar erro tardio. | Watchdog encerra o Job Object completo (incluindo Python) e verifica ausência de ambos. | `TREE_TERMINATED` | `UNKNOWN` -> `TERMINATED` (se `CONFIRMED_ABSENT` + `TREE_TERMINATED`) | **Apenas se** `TREE_TERMINATED` + `CONFIRMED_ABSENT` | Não |
| **7** | **Processo sem possibilidade de identificação confiável** | Risco de matar navegador errado ou deixar processo ativo. | Watchdog **não** encerra processo genérico; registra `INCONCLUSIVE`. | `INCONCLUSIVE` | `UNKNOWN` / `UPLOAD_UNKNOWN` | **Não (NO-GO para retry automático)** | **Sim (obrigatória)** |
| **8** | **PID reutilizado pelo Windows** | Matar processo de outra aplicação; falso positivo de encerramento. | Validação de `process_create_time` e Job Object detecta divergência; processo atual é ignorado. | `INCONCLUSIVE` (se Job Object também inacessível) | `UNKNOWN` / `UPLOAD_UNKNOWN` | **Não** (salvo se Job Object vazio comprovar) | **Sim** |
| **9** | **Watchdog encerrado inesperadamente** | Execução fica sem monitoramento temporariamente. | Ao reiniciar, watchdog recupera estado do State Store local e assume monitoramento/encerramento. | Recuperada após reinício (`TREE_TERMINATED` ou `INCONCLUSIVE`) | `UNKNOWN` / `UPLOAD_UNKNOWN` | **Não** até recuperação e verificação | Não (se recuperar) / Sim (se falhar) |
| **10** | **Falha ao persistir a evidência** | Cloud Hub nunca recebe prova de encerramento. | Watchdog não considera encerramento comprovado para fins remotos; job permanece bloqueado. | Nenhuma durável | `UNKNOWN` / `UPLOAD_UNKNOWN` | **Não** | **Sim** |
| **11** | **Evidência enviada ao Cloud Hub depois de uma nova tentativa** | Evidência antiga alterar estado de tentativa nova. | Cloud Hub valida `attempt_id` + `fencing_token` e rejeita/ignora efeito sobre tentativa mais recente (`409`). | Evidência antiga registrada apenas em log/auditoria | Tentativa nova **não** é afetada | N/A | Não |
| **12** | **Dois watchdogs tentando recuperar a mesma execução** | Condição de corrida no encerramento e envio duplicado. | Mutex Windows (`Local\DCF_WATCHDOG_LOCK_<worker_id>`) garante 1 watchdog ativo; `event_id` + `UPDATE` atômico com `fencing_token` no Hub evitam duplicidade. | `event_id` idempotente | Consistente (`UNKNOWN` -> `TERMINATED` uma única vez) | Conforme regra padrão | Não |
| **13** | **Upload concluído no YouTube, mas resposta perdida** | Retry geraria vídeo duplicado no YouTube. | Reconciliação no YouTube Studio retorna `FOUND_PUBLISHED`. | `video_url` encontrada na reconciliação | `CONFIRMED` / `PUBLISHED` | **Não (proibido retry)** | Não |
| **14** | **Resultado da reconciliação inconclusivo (`CHECK_FAILED` / `MULTIPLE_CANDIDATES`)** | Vídeo pode já existir no YouTube. | Mesmo com `TREE_TERMINATED`, falta `CONFIRMED_ABSENT`. Job permanece bloqueado. | `TREE_TERMINATED` + `CHECK_FAILED` | `UNKNOWN` / `UPLOAD_UNKNOWN` | **Não** | **Sim (obrigatória)** |
| **15** | **Reinício do computador durante o processo de encerramento** | Encerramento interrompido no meio. | No boot seguinte, compara `current_boot_time_utc > attempt_boot_time_utc` (via `Win32_OperatingSystem.LastBootUpTime`, ambos normalizados para UTC). Se verdadeiro, emite `EXECUTION_ISOLATED`; se evidência inconclusiva, estado vai para `UPLOAD_UNKNOWN` com retry automático proibido. | `HOST_BOOT_TIME_CHECK` (`EXECUTION_ISOLATED` ou `INCONCLUSIVE`) | `UNKNOWN` -> `TERMINATED` *(se `CONFIRMED_ABSENT` + evidência vinculada a `attempt_id` e `fencing_token`)* / `UPLOAD_UNKNOWN` *(se inconclusivo)* | **Sim**, somente após `CONFIRMED_ABSENT` + evidência de reboot válida + vínculo com `attempt_id` e `fencing_token` | **Sim (obrigatória)** se evidência inconclusiva |
